# 内容编写规范

> 最后更新：2026-08-19
> 适用对象：所有 Markdown 文档和教学内容

## Markdown 文档规范

### 标题层级

```
MUST: 每篇文档只有一个 H1（# 标题）
MUST: 标题层级不跳级（H1 → H2 → H3，不 H1 → H3）
SHOULD: H2 之间用 --- 分隔线隔开
```

### 代码块

```
MUST: 代码块必须标注语言类型

✅ ```python
✅ ```yaml
✅ ```json
❌ ```（无语言标注）
```

### 链接格式

```
SHOULD: 使用相对路径链接项目内文件
✅ [当前课程](../docs/courses/collision-pi.md)
✅ [wiki/glossary.md](../wiki/glossary.md)

MUST: 外部链接使用完整 URL
✅ [Keep a Changelog](https://keepachangelog.com/zh-CN/1.0.0/)
```

## 教学内容规范

### 心物比喻配对规则

```
MUST: 每个抽象概念首次出现时，必须配一个物理世界比喻
MUST: 比喻必须自洽——同一篇文章中不能混用比喻体系
      - 电力走电线 → 逻辑走道路（不能变成"逻辑水管"）
      - 城市体系 → 城市体系（不能突然跳到"农场体系"）
SHOULD: 比喻紧跟在概念定义之后，不超过两句话
```

✅ 正确示例：
> 坐标缩放就像把一张压扁的图纸在左右方向按比例拉伸——拉伸后压扁的城区恢复成完美的圆形广场。

❌ 错误示例：
> 坐标缩放很重要。就像做饭时要调整火候一样。

### 题目类型边界

客观知识题和状态观察题是两种不同的数据：

```text
客观知识题：
MUST: 具有可验证的正确答案
MUST: 单选题恰有一个正确选项
MUST: 多选题明确正确选项集合
MUST: 多空填空题为每一空提供 accepted_answers
MUST: 作者端保存解析，学生答错时不直接下发答案或解析

状态观察题：
MUST NOT: 设置正确答案或计入知识正确率
MUST: 说明观察目的和数据用途
MUST: 与客观题使用不同 question_type
当前版本: 暂不生成
```

### 学习媒体引用规范

```
MUST: 媒体只绑定一个知识节点
MUST: 视频素材标注来源和时间点，项目原生图标注为原生示意图
MUST: 图片旁文字只描述画面、概念和观察重点
SHOULD: 抽象变化优先使用可暂停、可重播的原生 SVG
```

### 双语术语规范

```
MUST: 首次出现的专业术语标注英文对应词
SHOULD: 中文在前，英文在括号中

✅ 相空间（phase space）
✅ 圆周角定理（Inscribed Angle Theorem）
❌ phase space（相空间）
```

## 数据文件规范

### JSON

```
MUST: 使用 JSON Schema draft 2020-12
MUST: 根级别包含 $schema 字段
SHOULD: description 字段用中文
```

### YAML

```
MUST: 顶层键使用 snake_case
MUST: 列表项使用 - 前缀（不是 * 或 +）
SHOULD: 多行字符串使用 | 或 > 标记
```

## 文档版本标注

```
MUST: 每个独立文档末尾标注版本和日期

> **文档版本**：v1.0
> **编制日期**：2026-07-11
```

对于有多个章节的文档：
```
MUST: 标注每个章节的完成状态

| 章节 | 内容 | 状态 |
|:---|:---|:---|
| 一 | 概述 | ✅ 完成 |
| 二 | 详细设计 | ⚠ 框架已定待细化 |
```
