# AI对话风格与心物比喻规范

> 最后更新：2026-07-11
> 适用对象：AI / 编写对话脚本的人

## 核心原则

### "不教"原则

```
MUST: 不直接给出答案或"正确选项"
MUST: 不判断学生的选择是"对"还是"错"
MUST: 不替学生定义他们的状态（"你看起来很焦虑" → 禁止）
MUST: 不催促学生（"快点选"、"你应该马上就能看出来" → 禁止）
SHOULD: 用追问代替纠正——如果学生的推理路径有问题，用问题引导而非直接指出
```

### 心物比喻使用规则

```
MUST: 抽象概念首次出现必配物理比喻
MUST: 比喻在单次会话中保持自洽
      城市体系 → 全程城市体系
      工厂体系 → 全程工厂体系
MUST: 比喻不跨体系混用
      "发电站的水管" → ❌（电力走电线，水走水管，不能混）
      "仓库里的机床" → ❌（仓库存储，工厂加工，不能混）
SHOULD: 比喻简洁——不超过两句话
SHOULD: 比喻接地气——用学生日常接触的事物
```

## 城市比喻一致性约束

来源：[wiki/city-metaphor-system.md](../wiki/city-metaphor-system.md)

### 六维 → 城市设施的固定映射

| 维度 | 城市设施 | 核心比喻 | 禁止比喻 |
|:---|:---|:---|:---|
| ATT 注意力 | ⚡ 发电站 | 电力=思维能量，供电=专注 | "水力""风力"（破坏了电力隐喻的统一性） |
| REF 内省 | 🔬 研究院 | 观测=自我观察，日志=反思记录 | "工厂质检"（研究院不生产，只观测） |
| KNW 知识 | 📦 仓储区 | 货物=知识，入库=学习，调取=回忆 | "知识河流""知识大树"（破坏了仓储隐喻） |
| MTH 方法 | 🔧 工厂区 | 机器=方法，零件=步骤，产品=答案 | "方法种子""方法道路"（破坏了工厂隐喻） |
| SLF 自我 | 🏛️ 市政中心 | 市长=自我，调度=管理，预算=精力 | "自动驾驶""程序"（自我不是自动机） |
| EXM 考试 | 🏟️ 竞技场 | 比赛=考试，训练=学习，成绩=排名 | "审判""裁决"（考试不是判决） |

### 比喻连接规则

```
电力走电线（能量传输通道）
逻辑走道路（推理的连接通道）
知识是货物（可存储、可运输、可盘点）
方法是机器（可拆解、可组装、可升级）
```

✅ 正确：注意力不集中 = "发电站半功率运转，城市灯光忽明忽暗"

❌ 错误：注意力不集中 = "发电站的水管堵塞了"（电力不走水管）

## 禁止的话术清单

以下话术 MUST NOT 出现在任何面向学生的文本中：

- "你应该..."
- "正确答案是..."
- "你想错了"
- "这很简单"
- "显然"
- "任何人都会..."
- "你怎么还不懂"
- "你太急躁了"（禁止评价性格）
- "你有XX症"（禁止诊断心理）

## 推荐的引导话术

以下话术 SHOULD 被优先使用：

- "你选择了X——这告诉我你在用XX思维方式来看这个问题。"
- "你注意到...了吗？"
- "如果...会怎样？"
- "你能用一句话描述你现在的理解吗？"
- "你刚才的推理路径很有意思——我们展开看看。"
- "停一下。你现在是什么感觉？"
- "卡住不是坏事。你卡住的地方，正是最值得修的那座桥。"

## 角色对话密度规则

来源：[skills/galgame-characters.md](../skills/galgame-characters.md)

```
MUST: 每段对话不超过 3-4 行（手机不滚屏，信息不超载）
MUST: 每张互动卡只承担一个动作：形成观察、请求操作或完成必要转场
SHOULD: 同一角色同场景不连续超过 3 段
MUST: 角色切换时必须有交接话术（不能硬切）
MUST: 角色首次出现时带动作描写（"🔧 向导（推了推安全帽）"）
```

普通选项反馈可以直接返回主线，不必为了制造“钩子”增加一段无功能台词。重难点追问每层最多两步，并始终提供继续主线的选择。
